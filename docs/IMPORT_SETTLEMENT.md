# 宅配便の関税納付と精算

公開版で公的照会先と精算の事前条件を確認できます。下部の検証結果は、過去版のデータ同梱配布物を使った記録です。

日本と中国本土の往復を含む国際宅配便を対象に、一般商品1品目・1個口の通常B2C輸入を扱います。DAPとDDPの両方で、加盟店サーバーが確認済みの配送業者・サービス・請求先を照合します。DAPは購入者と受取人が同じ注文を対象とします。

発送国と輸入国を方向ごとに扱い、反対方向の税表、貿易審査、配送業者の受諾は流用しません。実際の積載国が発送国と一致する直送が対象です。商品の原産国は発送国と区別します。国内、通常のEU域内配送、特別税関領域、経由便はこの宅配便の精算対象外です。北朝鮮を発送元・仕向地とする経路は対象外です。既存の貿易審査や輸入制限に該当する場合は、その確認が優先されます。

売買条件の費用負担と、配送業者が受諾した請求先は別々に記録します。配送業者のサービスや口座の適用条件は、実際の出荷について確認します。 [ICCのIncoterms® 2020チェックリスト](https://library.iccwbo.org/content/clp/Others/incoterms_2020_checklist_2024-update.pdf) ・ [DHL Expressの関税・税の請求ガイド](https://mydhlplus.dhl.com/content/dam/downloads/global/en/customs-guide/express_global_customs_customer_guidelines.pdf.coredownload.pdf)

## 経路と輸入日の事前確認

```sh
curl 'http://127.0.0.1:3008/v1/import-settlement/coverage?originCountry=JP&destinationCountry=CN&date=2026-11-14' \
  -H "Authorization: Bearer $VEYGRIT_CUSTOMS_API_KEY"
```

発送国・輸入国・日付を指定します。日付を省略すると日本時間の当日です。事前確認で取得した経路と税表の状況に基づき、次の荷物審査に進むか、通関領域、取引制限、税表の適用日を確認します。事前確認から金額、請求先の承認、発送許可は発行されません。商品分類、原産国、積載国、税率・費用、輸入者と配送業者の受諾は、実際の荷物について確認します。

| 応答 | 次に確認すること |
| --- | --- |
| `shipment_review_required` | 商品と経路に適用できる税表・条件付き計算ルール・原則ゼロの制度、費用、通関担当と配送業者の証跡 |
| `tariff_evidence_required` | 輸入日に有効で、見積もりに使える税表または他の関税根拠 |
| `route_review_required` | 通関領域、貿易同盟、取引制限など、`reasons` にある項目 |
| `date_review_required` | 過ぎた輸入日は資料の照会に使い、発送前の見積もりには新しい輸入予定日を指定 |
| `out_of_scope` / `blocked` | 対象外の経路または取引停止理由 |

応答は公開税表、参照用資料、確認日が照会時点より後の資料を区別します。収録済みの税表があっても、品目別の適用、原産地特恵、追加税や通関手数料は荷物単位で確認します。

1か国・地域を基準に相手先を一覧にする場合は `GET /v1/import-settlement/destinations` を使います。日本からの発送なら `originCountry=JP`、日本への輸入なら `destinationCountry=JP` を指定します。どちらか一方を指定し、必要に応じて `date` を追加します。対象国自身を除く247の相手先について、経路ごとの確認状況と件数を取得できます。

## 見積もりと発送前の確認

1. 加盟店サーバーは、認証済みの加盟店・注文から最新のカート、配送条件、住所利用許可を読み込みます。既存の `quoteVeygritOrder` を使う場合は、許可の有効期限を含む最新の注文スナップショットを使います。通関サービスのサーバー用キーは加盟店のサーバーで管理します。
2. `POST /v1/worldwide/quote` で方向・輸入日を確認した見積もりを取得します。`POST /v1/import-settlement/plan` に同じ `quoteRequest`、`quoteProfile: "worldwide"`、現在の `merchantId`、`shipmentId`、配送サービス、関税等の指定請求先、輸入者・通関担当の審査参照を渡します。最初の応答にある `scopeDigest` が、この方向の請求条件を識別します。中国本土→日本の既存の `POST /v1/pilot/quote` 連携は従来の入力を使えます。
3. 配送業者が受諾した請求先・口座を、発送システムで受領した応答または確認済みの受付記録と照合します。確認済みの参照ID、確認日時と期限、受諾された請求先、手順2の `scopeDigest` を `carrierAcceptance` に入れ、同じAPIで再確認します。配送業者・サービスや請求先、見積もり内容、連携済みの注文・住所の版が変わると再確認が必要になります。
4. `ready` は、送信された請求先と確認済みの受諾記録が一致した状態です。引き渡し直前に加盟店サーバーは、発行・保存した見積もり自体の期限、現在の注文版・住所利用許可、輸入者の適格性、配送業者の受諾と期限を再確認します。 `shippingAuthorized` と `productionAuthorized` は `false` を返します。未確認・不一致・期限切れは `review_required`、対象外の経路は `out_of_scope` です。

発送前に、発行済み見積もり、`ready` 時の `billingBinding`、確認日時と受諾記録の参照を加盟店サーバーに保存します。口座番号の代わりにアクセス制限された参照IDを使います。受付証跡の取得、真正性の確認、加盟店のアクセス権、発送可否の決定は、APIを呼ぶサーバーが担当します。このAPIは配送業者への申請や口座照会を実行しません。

| --- | --- | --- |
| DDP・販売者側の請求先を確認済み | 300,000円 | 0円 |
| DAP・購入者側の請求先を確認済み | 300,000円 | 38,100円 |
| 請求先が未確認、不一致または期限切れ | 有効な見積もりの金額 | 確認中 |

表の金額は中国本土→日本の模擬注文です。発行済みの見積もりと実際のWooCommerce注文金額を別々に扱います。`attach_order_preview()` に最新の確認結果を渡すと、注文・出荷・発行済み見積もりの内容・データ版・請求条件・有効期限を照合して輸入時の金額を表示します。初期対応は見積もり、WooCommerce注文、納付・請求・支払いの証跡が同じ審査済み通貨のケースです。異なる通貨は確認を要し、自動換算による精算は行いません。 [WooCommerce連携](../integrations/woocommerce/README.md)

## 通関後の照合

`POST /v1/import-settlement/reconcile` に、発送前に保存した `billingBinding` に実際の申告参照 `declarationId` を加えた `scope`、発行済みの `estimate`、取得済みの証跡を渡します。各証跡を正規化する際に、加盟店・注文・出荷・申告・配送サービス・請求先・発送国・輸入国・`settlementCurrency` を照合して付与します。照合サーバーは対象を認証済み加盟店の保存記録から読み込みます。見積もりの日付、納付日、請求日と支払日は既存の日本時間の業務日で照合します。既存の中国本土→日本の記録は、`settlementCurrency` が省略された形でも照合できます。

| 証跡 | 確認すること |
| --- | --- |
| `remittances` | 税関への納付。関税・輸入税・追加関税・物品税を費目別に記録 |
| `carrierInvoices` | 配送業者からの請求。税関への納付と同じ税額を突合し、通関手数料と配送業者の手数料を別計上 |
| `carrierPayments` | 配送業者への支払い。請求番号、請求通貨、精算済み金額を照合 |

税関への納付確認と配送業者への精算確認は独立した状態を持ちます。納付済みでも配送業者への支払いが未確認なら精算は保留です。同じ証跡ID・同じ内容を再送した場合は、1件として数えます。同じIDで内容が異なる場合、対象の請求先が異なる場合、税額が一致しない場合、過払いまたは未分類の費目がある場合は要確認です。確定した0円を明細に含め、情報が欠けた費目は保留します。

比較できる費目に見積額と請求額の差があれば、他の費目が未確定でも `ESTIMATE_INVOICE_DIFFERENCE` を返し、精算を要確認にします。

初期版は、出荷1件に対して1申告・1請求の記録を照合します。日本郵便への納付委託、通知書による納付、NACCS直接納付、第三者請求、複数個口、返金・追徴、購入時の関税等の預りは後続の実装です。 [日本税関 6101 国際郵便物の通関手続](https://www.customs.go.jp/tetsuzuki/c-answer/kokusaiyubin/6101_jr.htm) ・ [日本税関 1313 リアルタイム口座振替](https://www.customs.go.jp/tetsuzuki/c-answer/imtsukan/1313_jr.htm)

```sh
node scripts/verify-published-settlement-matrix.ts --report ./published-settlement.json
```

### rc.19の検証記録

rc.19は北朝鮮を除く248の国・地域で、発送元と輸入先が異なる61,256方向を事前確認します。南極は対象地域の台帳から外れ、コソボは補足コード `XK` で照会できます。正の精算試験には、既存の80仕向地の税番を基にした隔離環境用の税表を使い、各方向でDAPとDDPを実行します。

| 検証 | 結果 |
| --- | --- |
| 2026年11月14日の同梱資料で事前確認 | 61,256方向。税表等の根拠が必要44,686、経路の審査が必要9,559、荷物単位の審査へ進める6,309、対象外702 |
| 11月13日の模擬税表で見積もりから精算まで | 19,760方向を試験し、17,404方向・34,808件が精算まで到達。発送元229、輸入先80、51通貨。2,356方向は保留または対象外 |
| 11月11日・12日の同梱公開税表を使う追加試験 | 52方向を試験し、47方向・94件が精算まで到達。5方向は保留 |
| 2種類の精算試験の重複を除いた範囲 | 17,427方向、輸入先103、両方向が通った組み合わせ2,794組。すべて隔離環境での検証 |

11月13日の模擬税表を用いた試験では、2,771組で両方向の精算を確認しました。試験用の税番がなかった168仕向地では、各1件で根拠が足りない場合に金額を保留することも確認しました。旧日の公開税表の試験は、その資料の適用日と確認日を再現します。本番の料金や配送業者の取扱可否には、実際の輸入日と出荷の証跡が必要です。 世界の事前確認・精算試験結果（配布物の `qa/import-settlement-coverage-rc19.json`） ・ 同梱公開税表の追加試験結果（配布物の `qa/import-settlement-historical-rc19.json`）

11月14日に有効な公開税表は同梱資料にありませんでした。荷物単位の審査へ進める6,309方向は条件付き計算ルールの候補で、その条件に合う商品、金額、申告内容の確認が必要です。

WooCommerceでは80の国・地域、166方向、51通貨のDAP・DDPを含む349件を試験しました。332件の保存済み見積もりを精算まで照合し、残り17件は税表・請求先・通貨などの確認が必要な場合の保留を検証しました。 WooCommerceの検証結果（配布物の `qa/import-settlement-woocommerce-rc19.json`）
