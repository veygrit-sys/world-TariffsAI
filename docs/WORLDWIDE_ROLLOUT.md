# 世界全方向の開発計画

全方向の開発を8回に分けます。第1回で方向照会と確認済み根拠による見積もりの共通機能を実装し、第2〜6回で輸入先ごとの根拠と検証事例を増やします。第7回で特別な通関方式と税関領域を検証し、第8回で実注文とデータ更新の運用を確認します。

## 全方向の数え方

台帳は北朝鮮（KP）を含む249仕向地です。発送元とお届け先が異なるコードの組み合わせは、向きを区別すると **61,752方向（249 × 248）** です。北朝鮮を発送元・お届け先から除いた地理上の組み合わせは **61,256方向（248 × 247）** です。税関領域、規制、運送会社の受付、注文の内容によって、各方向で提供できる機能が決まります。 [国・地域台帳と税表の対応範囲](DESTINATION_COVERAGE.md) ・ [商用対象と取引確認](TRADE_POLICY.md)

発送元、お届け先、船積地域、明細ごとの原産地を別々に取得します。例えば、日本からドイツへの見積もりはドイツ向けの輸入条件を、ドイツから日本への見積もりは日本向けの輸入条件を確認します。輸入先に共通する税表と手続を再利用し、方向ごとの輸出条件・原産地・配送条件を照合します。国内配送は国内の手続に沿って案内します。

## 8回の分割

| 回 | 範囲 | 作るもの | 完了時に確認すること |
| --- | --- | --- | --- |
| **1** | 全方向の共通基盤 | 輸入日を指定できる全方向の照会、確認済み根拠を使うB2C見積もり、検証状況の表示 | 既存の日中米6方向と他地域の合成貨物で、方向照会から見積もり・請求照合までを試験する。北朝鮮発着の受付停止、日本向けの北朝鮮原産・船積みの受付停止、根拠不足時の保留を確認する |
| **2** | 東・東南・南・中央アジア（33仕向地） | 仕向地別の税表・輸入税・手数料・通関方式を登録する。日本・中国本土の既存検証例から適用条件を見直す | 品目、原産地、申告日を固定して公的税表と照合する。発送元とお届け先を逆にしたときに輸入先の根拠が切り替わることを確認する |
| **3** | 欧州（52仕向地） | EU共通の税表と仕向地別の税・費用、EU外の仕向地の根拠を登録する | 域外からの輸入、域内移動、特別な税関領域の判定を確認する。暫定措置や追加税の適用日を境界値で試験する |
| **4** | 北米・中南米・カリブ（57仕向地） | 米国の既存検証例を含め、税表・輸入税・追加措置・手数料の根拠を登録する | 取引価格、原産地、輸入方式、追加措置によって変わる費目を検証する。購入時と輸入時の支払い、請求差額まで照合する |
| **5** | 西アジア・アフリカ（78仕向地） | 地域の共通税表、輸入先独自の税・費用、輸入許可・取引条件の参照先を登録する | 共通税表の適用と国内例外を確認する。取引相手や輸送経路の根拠が不足する注文が保留されることを試験する |
| **6** | オセアニア（29仕向地） | 現地税関・運送会社の情報を登録し、島しょや属領ごとの税関領域・書類・受付条件を確認する | 親国のコードや税率を適用する条件を公的資料で照合する。関税が0となる場合も、他の税・費用・書類を個別に確認する |
| **7** | 特別な制度・税関領域 | 特別地域、少額・越境EC特例、贈答・返品・B2B、特恵税率、従量・複合税を制度ごとに扱う | 仕向地・適用期間・必要証拠が一致する事例と、条件不足や期限切れの事例を試験する。通常輸入の見積もりと同じ費目が二重計上されないことを確認する |
| **8** | 実注文と継続運用 | ECの購入時見積もり、通関担当への引き継ぎ、通関後の請求照合を実注文で確認する。税表改定と再見積もりを運用する | 商用公開する方向ごとに、代表的な品目・配送条件の実注文と差額理由を記録する。税表の更新、期限切れ、更新失敗からの復旧を試験する |

地域別の整備は輸入先を基準に割り当てます。国連M49の区分に沿い、南アジアに分類されるイランは第2回、地理区分が西アジアのキプロスとトルコは第5回に含めます。Veygritの台帳では `TW` を第2回、`XK` を第3回に割り当てています。各回の仕向地数には商用対象外も含まれます。第7回では各仕向地の特別な税関領域や制度を扱います。 [国連M49の国・地域区分](https://unstats.un.org/unsd/methodology/m49/overview)

## 第2回・第3回の結果

東・東南・南・中央アジアと欧州の仕向地別の確認事項を方向照会と通関準備に追加しました。税関・VAT等の領域が異なる欧州の一部の方向は個別確認へ進みます。追加データとAPI・CLIの例は [アジア・欧州の輸入手続と税表](ASIA_EUROPE_CUSTOMS.md) に記載しています。

## 第4回の結果

北米・中南米・カリブ57仕向地の手続資料、指定日別の標準税表、追加措置と手数料の参照を追加しました。 [米州の追加範囲](AMERICAS_CUSTOMS.md)

## 第5回・第6回の結果

西アジア・アフリカ78仕向地とオセアニア・島しょ地域29仕向地の公的資料を追加し、輸入許可・税関と検疫領域・書類の確認を方向照会と通関計画に組み込みました。 [第5回・第6回の収録状況](WESTERN_ASIA_AFRICA_OCEANIA_CUSTOMS.md)

## 第7回の結果

特別税関領域25件と、36仕向地の輸入特例58件を方向照会・通関計画に組み込みました。EU暫定関税は確認済み申告明細数を使い、特恵税率は品目・原産地・協定を照合して参照値を表示します。 [第7回の収録状況](SPECIAL_CUSTOMS_PROCEDURES.md)

## 貿易同盟、経由貨物と第8回の準備

同盟の加盟・経過措置を方向照会に加え、経由順と税関管理の証拠を通関計画・見積もりに組み込みました。税表の切替を検証するコマンドと日中米6方向の実注文検証手順を追加しました。 [同盟と経由貨物](TRADE_BLOCS_AND_TRANSIT.md) ・ [実注文検証](PILOT_LIVE_VALIDATION.md)

## 第1回の使い方

| API | 確認すること |
| --- | --- |
| `GET /v1/worldwide/coverage?date=YYYY-MM-DD` | 台帳の仕向地数、方向数、指定日の対応範囲 |
| `GET /v1/worldwide/direction?originCountry=JP&destinationCountry=DE&date=YYYY-MM-DD` | 発送元からお届け先への方向の扱いと、利用できる根拠 |
| `POST /v1/worldwide/quote` | 注文・貨物と紐づく確認済み根拠から、費目、負担者、支払時点、期限を算出できるか |
| `POST /v1/customs/plan` | 通関書類、税関領域、品目・原産地の確認事項 |
| `POST /v1/worldwide/reconcile` | 保存済み見積もりと請求額の費目別の差 |

CLIでは `worldwide-coverage`、`worldwide-direction FILE`、`worldwide-quote FILE [ISO_TIME]` を使います。ブラジルからドイツへの合成例を同梱しています。 [方向照会例](../examples/worldwide-direction-br-de.json) ・ [見積もり例](../examples/worldwide-quote-br-de.json) ・ [OpenAPI](openapi.json)

見積もりには、貨物と紐づいた費目別の根拠と、発送元・お届け先に対応する取引確認 `tradeReview` が必要です。取引確認は、官庁または通関担当が確認した記録と適用期間を添えます。通関や配送を制限する条件、根拠の不足、特別な税関領域を検出した場合は確認に回します。実注文の通関・請求照合は第8回の検証対象です。

ECから注文に紐づけて試算する場合は `quoteVeygritWorldOrder` を使い、`WorldOrderSnapshot.worldQuote` に取引確認と費用根拠を保存します。既存の注文版と住所利用許可の確認を使い、結果の有効期限は許可の期限内に収めます。 [見積もり・請求の連携手順](V1_PILOT.md)

## 第2回以降で追加する記録

- **輸入先の根拠**として、税関領域、品目番号、適用開始・終了日、税率・税額、課税標準、原産地条件、通貨、端数処理、出典URLを保存します。公的データベースは参照先を探す際に使い、見積もりの根拠を輸入先の公的資料または担当者が確認した記録にひも付けます。 [WCOの品目分類に関する案内](https://www.wcoomd.org/en/faq/harmonized_system_faq) ・ [WTOの税関評価資料](https://www.wto.org/english/tratop_e/cusval_e/cusval_info_e.htm) ・ [WTOの関税・貿易データ](https://ttd.wto.org/en)
- **費用と通関の検証**では、基礎関税、輸入VAT・GST、追加税、物品税、税関手数料、配送会社手数料、購入時税を照合します。追加した制度ごとに、計算できる貨物と要確認になる貨物を再現し、実際の購入・申告・請求と照合する事例を残します。 [請求照合仕様](INVOICE_RECONCILIATION.md)
- **更新運用**では、税表の版・適用日を見積もりに残し、更新後の税額を再現できることを確認します。期限が切れた見積もりは再見積もりに戻し、更新に失敗した場合は照合済みの版に戻して検証します。 [出典と税制データの更新](DATA_UPDATES.md)
